Chce sprawdzić Soloist jako możliwy tor odtwarzania i umożliwić osobistą konfigurację odbiorcy. Potwierdził, że samo sterowanie Soloist bez katalogu daje za mało: pełny wariant ma łączyć własny Client ID do katalogu z osobnym kluczem Soloist do odtwarzania. To zastępuje założenie, że brak wspólnego Client ID wyklucza jakąkolwiek konfigurację Spotify przez odbiorcę; nie jest zatwierdzeniem nieograniczonego dostępu Public ani wydania.

8.11.2026 użytkownik wyraźnie upoważnił do pobrania, lokalnego przygotowania i bezokienkowego sprawdzenia Soloist. To zastępuje wcześniejszą instrukcję w sekcji „Wdrożenie i odbiór”, która odkładała te czynności do osobnej zgody. Użytkownik pracuje na innych plikach, dlatego żadna próba nie może przejąć fokusu ani uruchamiać widocznego okna.

## Potwierdzone granice Spotify

- Web API w trybie Development Mode wymaga Premium właściciela aplikacji, ma najwyżej pięciu wskazanych użytkowników i listę dopuszczonych kont. Własny Client ID odbiorcy może służyć jego osobistej aplikacji, ale nie usuwa ograniczeń Spotify ani nie zmienia AMC w zatwierdzoną aplikację o nieograniczonym zasięgu. Źródło: https://developer.spotify.com/documentation/web-api/concepts/quota-modes
- Soloist wymaga osobnego klucza API wygenerowanego przez każdą osobę z Premium. Nie wolno współdzielić klucza ani dołączać binarki Soloist do instalatora AMC. Oficjalna wersja Windows jest pobierana przez użytkownika i wygasa po 90 dniach. Źródła: https://developer.spotify.com/documentation/soloist/concepts/authentication ; https://developer.spotify.com/documentation/soloist/reference/downloads-and-updates
- Soloist loguje się przez Spotify Connect: uruchomić urządzenie z kluczem, a następnie wybrać je w oficjalnej aplikacji Spotify w tej samej sieci. To nie jest kod urządzenia wpisywany na stronie jak w niektórych usługach. Ponowne uruchomienia zachowują sesję, jeśli katalog danych jest ten sam. Źródło: https://developer.spotify.com/documentation/soloist/concepts/authentication
- Lokalny WebSocket Soloist obsługuje stan, kolejkę i sterowanie odtwarzaniem. Nie zastępuje Web API do wyszukiwania, biblioteki i edycji playlist. Uruchamiać go tylko na 127.0.0.1, ponieważ API nie ma własnego uwierzytelniania. Źródła: https://developer.spotify.com/documentation/soloist/howtos/basic-integration ; https://developer.spotify.com/documentation/soloist/reference/websocket-api
- Lokalny WebSocket przyjmuje `play` z opcjonalnym Spotify URI utworu, albumu, playlisty albo odcinka. `add_to_queue` przyjmuje tylko URI utworu. Nie dokumentuje polecenia zmiany prędkości, mimo że stan zawiera pole `options.playback_speed`. Źródło: https://developer.spotify.com/documentation/soloist/reference/websocket-api
- CLI Soloist wymaga podania klucza przy każdym starcie przez `--api-key`; klucz jest sekretem. Przed automatycznym uruchamianiem z AMC trzeba zaprojektować przechowywanie w magazynie poświadczeń i nie wypisywać klucza do komunikatów, diagnostyki ani historii poleceń. Źródło: https://developer.spotify.com/documentation/soloist/reference/command-line

## Proponowany przebieg w AMC

1. `Ctrl+F5` otwiera konto Spotify. Przycisk „Konfiguruj odtwarzacz Soloist” otwiera osobne okno konfiguracji. Każda część ma własny stan. Początkowy fokus i etykiety NVDA mają wskazać pierwszy wymagany krok. Klucz i Client ID nie trafiają do zwykłych etykiet NVDA.
2. Katalog: „Otwórz panel aplikacji Spotify”, „Skopiuj adres powrotu”, pole „Client ID”, „Zapisz” i „Zaloguj w przeglądarce”. Własna aplikacja odbiorcy i jej limity są wyjaśnione przed logowaniem. Istniejąca obsługa PKCE w AMC pozostaje podstawą.
3. Soloist: „Utwórz własny klucz Soloist”, „Pobierz Soloist ze Spotify”, wybór dokładnego `soloist.exe`, pole klucza, „Uruchom urządzenie”, „Sprawdź połączenie” i „Połącz ponownie”. AMC instruuje, by wybrać nazwane urządzenie w oficjalnej aplikacji Spotify. Hasło konta pozostaje poza AMC.
4. Po sparowaniu AMC używa `soloist ctl` do stanu i sterowania. Nie przedstawia kolejki lokalnej AMC jako kolejki konta. Soloist na Windows używa domyślnego wyjścia WASAPI, więc obecne `Shift+A` Chrome nie jest obiecane dla Soloist.
5. Brak Client ID nie usuwa Soloist jako ograniczonego odtwarzacza/sterownika, lecz wtedy AMC nie pokazuje pełnego katalogu ani playlist przez Web API. Brak klucza Soloist pozostawia obecny tor Chrome w Test.

## Szkic instrukcji użytkownika do odbioru

> Otwórz Spotify w AMC i naciśnij `Ctrl+F5`. Do katalogu wpisz własny Client ID aplikacji Spotify i zaloguj konto przez przeglądarkę. Następnie wybierz „Konfiguruj odtwarzacz Soloist”, wskaż pobrany ze Spotify plik `soloist.exe`, wpisz własny klucz Soloist i wybierz „Zapisz ustawienia” oraz „Uruchom urządzenie”. W oficjalnej aplikacji Spotify wybierz urządzenie „AMC Test” albo „AMC Public”. Po potwierdzeniu połączenia AMC użyje Soloist przy następnym odtwarzaniu. Klucz i hasło pozostają prywatne; hasło wpisuj tylko na stronie Spotify. Jeśli Soloist nie jest gotowy, AMC korzysta z dotychczasowego odtwarzacza Chrome.
